# BDeckのコード配置

元ブラウザの共通処理は元のファイルに残し、X専用の実装を次のディレクトリにまとめています。

| 場所 | 内容 |
| --- | --- |
| `crates/zephium-core/src/deck/` | アカウント識別、カラム、配置、表示設定のモデルと検証 |
| `crates/zephium-app/src/shell/deck/` | X用のアカウント画面、投稿パネル、カラム操作 |
| `crates/zephium-engine/src/host/deck/` | XのDOMに適用するCSSと表示用スクリプト、受信メッセージの検証 |
| `desktop/src/deck/` | BDeckのネイティブ操作を受け付けるIPCとメニュー |
| `frame/src/domain/deck/` | Rustが確定したアカウント・カラム情報の画面への反映 |
| `frame/src/features/deck/` | カラム一覧、操作バー、アカウント画面、BDeckの表示設定 |

WebViewの生成・破棄、プロファイルの保存と消去、OSのウィンドウ処理、設定画面からの復帰などは、元ブラウザの処理を必要な範囲で使用します。共通ファイルには、これらとBDeckを接続する処理を置きます。AIやWorkの機能は復元しません。

アカウントは、BDeckが生成した固定IDとプロファイルIDでログイン領域を分離します。X側の数値IDは、読み込み済みページのDOM内にある初期データから確認し、文字列として保存します。表示名と`@ユーザー名`は表示用の情報です。任意のアカウント名を利用者に設定させる処理はありません。

左の＋から開く追加パネルと、各カラムの歯車から開く設定パネルは`desktop/src/deck/column_panel/`が所有します。画面は`frame/column.html`から必要時に1つだけ生成し、閉じると非表示にして再利用します。元ブラウザのWebView保護とWindowsの終了確認を共用し、XのWebViewやログイン領域は追加しません。操作はメイン画面の既存の設定保存経路へ渡します。

追加と設定は`ColumnFields.svelte`と画像付きの`AccountPicker.svelte`を共用します。投稿パネルのアカウント選択も同じネイティブパネルと`AccountPicker.svelte`を使い、OSの文字だけのメニューは作りません。専用のカラム一覧・デッキ管理画面はありません。アカウントと表示設定は上部の各ボタンから開き、画面内で相互移動しません。

アカウント画像は読み込み済みXページのアカウントボタンから参照し、変更を監視します。表示には通常の画像読み込みを使用し、画像URLごとに要素を置き換えます。画像が削除された場合は保存した参照も取り除きます。プロファイル削除の保存処理では、関連するカラム・アカウント情報と画像の参照を同じトランザクションで削除します。

広告の非表示は`deck.hide-advertisements`で切り替えます。既存の外観設定と同じスタイル適用経路を使い、`placementTracking`を含むセルをCSSで非表示にします。Xへの操作の送信や広告通信の遮断は行いません。

アカウントの追加は元ブラウザのプロファイル作成処理からRust側で反映します。画面側で未登録プロファイルを自動追加する処理はありません。削除はOSの確認ダイアログを経て、元の削除ジャーナル・ネイティブ消去・保存ファイルの消去経路を使用します。画面は処理の受付時点で完了とせず、既存の処理完了通知を待ちます。

カラムの表示位置とログイン領域は別々に管理します。削除時は表示先のスペースではなく実際の所有プロファイルを確認し、ほかのアカウントのカラムと保持中の投稿パネルを残します。最後のアカウントを削除した場合は、元ブラウザの初期スペース生成処理で新しいアプリ用プロファイルを作ります。そのプロファイルをXアカウントとして自動追加することはありません。

カラム・表示設定の変更は、IPCのキュー受付だけで成功扱いにせず、元ブラウザの`OperationProcessed`通知を待ちます。`store_pending`と`native_pending`は保存処理や描画の継続中として扱います。カラムとアカウントの一覧はRust側の`deck.state`通知で更新し、画面側から古い一覧を再反映しません。アカウント削除の完了表示には、保存とネイティブ消去が完了した`profile_deletion_completed`を必要とします。

投稿パネルはアカウントごとに保持します。開き直す操作では既存のWebViewと入力内容を残し、既存の編集欄へフォーカスします。利用者の操作で別ページへ移動していた場合だけ、通常のURL遷移で投稿画面を開きます。
